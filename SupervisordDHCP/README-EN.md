# Objectives

The objective of this lab is to create a simple topology using `supervisord` to manage services and `kea` to provide an L2 network with access to the LAN1 network and the Internet via `iptables`.

## Why Supervisord?

To have more than one service per container, we need a process controller. Supervisord is simple and useful.

Although having more than one service per container breaks the primary idea of containerized system architecture 
(one container per service), sometimes it isn't always possible. For this reason, we need to learn how to work with a simple process manager.

For embedded systems and lightweight environments, Supervisord is a great utility.

But these are not the main reasons. We will use `supervisord` inside a container because we want to simulate a server with multiple services. Instead of using a heavyweight virtual machine, we use containers to build complex topologies that, if built with virtual machines, would require NASA-grade computers.

If implementing a multi-service server, unless it is strictly necessary, we will never run more than one service per container.

## Why use KEA?

In intermediate and advanced IT vocational training cycles in Spain, `isc-dhcp-server` is the standard for DHCP services. Many relatively old servers (2-3 years or older) still use this service.
**It is completely outdated** and has been completely dead since 2022.

`KEA` is the new standard DHCP service created by `ISC` with an absolutely incredible configuration file structure.

# Preparation

The `alpine-router` device will have a NAT network interface generated by Docker and another one called `LAN1I` for the LAN1 network.

The `LAN1` device is an Open vSwitch L2 switch.

The `alpineX` clients are simple containers with BusyBox and the `udhcpc` DHCP client.
The network is `10.10.10.0/24` with a gateway of `10.10.10.1/24` and a DHCP range of `10.10.10.10-10.10.10.40/24`.

The `alpine3` client will have the IP `10.10.10.50`.

# Requirements

- Open vSwitch, `ovs-docker`, and Docker installed.
- Internet connection.
- A user with Docker and Open vSwitch permissions.

# How to Replicate

1. Run `run.sh` with bash.
2. Run `kill.sh` to destroy the entire topology.

- You can access Supervisord using the container's IP and port `10000`.
- DHCP starts automatically.
